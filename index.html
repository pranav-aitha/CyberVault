How Modern Systems Protect Passwords

Responsible websites never store your password in plaintext. Here is an interactive walk-through of how Hashing, Salting, and Peppering safeguard your credentials in real databases.

Stage 1: One-Way Hashing

Cryptographic Digest (SHA-256)

A mathematical function transforms any length input into a fixed 256-bit fingerprint. It is strictly one-way (irreversible), but deterministic: identical inputs always yield identical outputs.

Computing...
Vulnerability: Attackers precompute billions of hashes into "Rainbow Tables". If raw SHA-256 is used, your password can be looked up instantly!
Stage 2: Adding a Unique Salt

Neutralizing Rainbow Tables

The system generates a unique, cryptographically random string (the "salt") for every individual account and prepends it before hashing: SHA256(password + salt).

Stage 3: Secret Server Pepper

Defense-in-Depth Against Database Leaks

A "Pepper" is an application-wide secret key stored in a Hardware Security Module (HSM) or server environment variables—never in the SQL database. Formula: SHA256(password + salt + pepper).

🛡️ If hackers dump the database via SQL injection, they have the hashes and the salts, but still cannot crack them because they lack the HSM pepper key!
Stage 4: Key Stretching (Argon2 / bcrypt)

Deliberate Computational Slowness

Raw algorithms like SHA-256 or MD5 were built for high speed (checking data integrity in nanoseconds). But high speed helps attackers test 100 billion passwords per second!

Modern standards (Argon2id, bcrypt, PBKDF2) run thousands of mathematical rounds and require substantial RAM. To a legitimate user logging in, a 250 millisecond delay is imperceptible. But to an attacker's GPU cluster, cracking speeds drop by over 1,000,000x!

How Do Breach Check Services (like HaveIBeenPwned) Check Your Password Safely?

They use a mathematical privacy principle called k-Anonymity:

  1. Your browser hashes your password into a 40-character SHA-1 string (e.g. 5BAA6...8FD8).
  2. Your browser sends ONLY the first 5 characters (5BAA6) to the breach API.
  3. The API returns a list of ~500 breached hashes that start with those 5 characters.
  4. Your browser searches the list locally on your computer for the remaining 35 characters.
  5. Result: Neither the API nor network eavesdroppers ever see your actual password!
